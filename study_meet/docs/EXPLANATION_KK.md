# StudyMeet жобасының толық түсіндірмесі

## 1 Мақсаты және алғашқы әрекеттер

StudyMeet студенттерге бірге дайындалатын оқу кездесулерін табуға арналған. Coding, Languages, Science, Design, Careers деген бес санат бар. Кездесуді қосуға, өңдеуге, жоюға, таңдаулыға сақтауға және қатысушылар тізіміне тіркелуге болады. Online қосылғанда аудитория орнына сілтеме енгізіледі. Интерфейс зертханадағы атауларды салыстыруға ыңғайлы болу үшін ағылшынша, нұсқаулық қазақша жазылды.

Алдымен Profile бетіне кіріп, атыңызды және қажет болса CS-2301 сияқты топты енгізіңіз. Save profile басыңыз. Discover ішінен кездесу ашып, Join session басыңыз, диалогты растаңыз. Participants бөлімінде атыңыз және You белгісі пайда болады. Leave session тізімнен шығарады. Толған кездесуге жаңа адам қосылмайды, бірақ бұрын тіркелген адам шыға алады.

## 2 Іске қосу

1. Архивті жеке қалтаға шығарып, pubspec.yaml тұрған қалтаны редакторда ашыңыз.
2. `flutter --version` арқылы Flutter бар екенін тексеріңіз.
3. `flutter pub get` тәуелділіктерді дайындайды.
4. `flutter run -d edge` немесе `flutter run -d chrome` браузерде ашады.
5. Android үшін эмуляторды қосып, `flutter devices` тізіміндегі құрылғыға `flutter run -d DEVICE_ID` орындаңыз.
6. Hot reload интерфейсті жаңартады, hot restart бастапқы деректерді қайта жасайды.

Сервер, дерекқор немесе API кілті қажет емес. Flutter SDK және flutter_lints қана тікелей тәуелділік ретінде жазылған. pubspec.lock ішінде Flutter өзі қолданатын транзитивті пакеттердің болуы қалыпты. example.com кездесулерінің мекенжайлары — тек мысал мәтіндер.

## 4 MyApp және тақырып

main() MyApp-ты іске қосады. MyApp StatefulWidget, өйткені ThemeMode өзгеруі мүмкін. `_mode` MaterialApp.themeMode мәніне беріледі. Ашық және қараңғы тақырыптар ColorScheme.fromSeed арқылы жасалады. Seed үшін Flutter-дің дайын colorScheme рөлі қолданылады; lib ішінде қолмен жазылған түс не fontSize жоқ.

Shell профиль бетіне таңдалған тақырып пен callback жібереді. Профильде Dark басылғанда callback MyApp-тағы `_mode` мәнін өзгертеді. MaterialApp қайта құрылады, Shell-дің State-і сақталады. Тақырыпты ауыстыру кездесулерді өшірмейді.

## 5 Meeting моделі неге өзгермейді

Meeting өрістері: id, title, category, when, place, limit, names, online, description, favourite. id өзгерген элементті тізімнен табуға керек. when бір DateTime ішінде күн мен уақытты сақтайды. description — String?, яғни null болуы мүмкін.

Барлық өріс final. Бірақ final List жалғыз өзі жеткіліксіз: оған add жасауға болады. Сондықтан ашық Meeting factory келген names тізімін List.unmodifiable арқылы көшіріп, жабық const Meeting._ конструкторына береді. Бастапқы тізімді кейін өзгерту де, getter арқылы алынған тізімді өзгерту де модельге әсер ете алмайды. Const конструктор мен қорғаныш factory бірге осы талапты орындайды.

copyWith ескі объектіні өзгертпей, жаңа объект жасайды. `item.copyWith(favourite: !item.favourite)` таңдаулы күйін ауыстырады. Мұндағы ! логикалық терістеу; null assertion емес. Жобада null assertion қолданылмайды.

copyWith параметріндегі null ескі мәнді сақтау дегенді білдіретіндіктен, сипаттаманы жоюға `clearDescription: true` бар. Бос сипаттаманы сақтағанда форма осы параметрді береді.

Meeting.empty() жаңа id, санат, ұсынылған уақыт және 12 орын сияқты бастапқы мәндерді береді. Жаңа формада күн мен уақыт өрістері бос: қолданушы оларды өзі таңдауы керек. Picker-дің бастапқы ұсынысы модельден алынады. Profile.empty() бос ат пен топ жасайды.

## 6 Getter, record және enum

count = names.length; free = limit − count; isFull = count >= limit. Бұлар жеке сақталатын өрістер емес, getter. Сондықтан адам тіркелгенде count-ты бөлек жаңартуды ұмытып кету мүмкін емес. isPast when мәнін DateTime.now()-мен салыстырады. contains(name) any арқылы атты іздейді. Dart getter параметр қабылдамайды, сондықтан contains — әдіс.

places бірден екі мән қайтарады: `({int taken, int free})`. Detail ішіндегі `final (:taken, :free) = _item.places;` record-ты екі айнымалыға бөледі. Бұл destructuring деп аталады.

Category enum-ында label және icon бар. color әдісіндегі switch барлық бес мәнді жеке қарайды. Алтыншы санат қоссаңыз, толық емес switch-ті анализатор көрсетеді. Chips және dropdown Category.values арқылы жасалғандықтан жаңа санат автоматты түрде көрінеді.

## 7 Бастапқы деректер

seedMeetings() күндерді бүгінге қатысты құрады: жобаны кейінірек ашсаңыз да өткен және болашақ мысалдар болады. m01 атауы дәл 60 таңба. m02-де үш орын және үш адам, яғни FULL. m03 кеше болған. m04 онлайн. m05-те сипаттама жоқ. Басқа мысалдар барлық санатты, бос тізімді, аз қалған орынды және таңдаулыларды көрсетеді.

Reset data диалогпен расталған соң seedMeetings()-ті қайта шақырып, профильді тазартады. Тақырып MyApp-та тұрғандықтан өзгермейді. Деректер файлға жазылмайды.

## 8 State және callback

Shell State ішінде `_items`, `_profile`, `_tab` бар. Tab-тар осы мәндерді конструктор арқылы алады. Жүрек басылғанда tab onFavourite callback-ін шақырады; Shell copyWith арқылы жаңа Meeting жасайды. `_replace` сол id бар элементті жаңасымен алмастырады. setState тек меншіктеуді қоршайды; оның ішінде диалог, навигация немесе await жоқ.

Деректер бағыты: MyApp → Shell → Tab немесе Detail. Әрекет callback арқылы кері жүреді. Form уақытша мәндерді өзінде ұстап, тек Save кезінде дайын Meeting қайтарады. Back арқылы шығу shell деректерін өзгертпейді.

Detail `_item` ішінде көрініп тұрған кездесудің көшірмесін ұстайды. Өзгергенде әрі shell callback-ін, әрі өзінің setState әдісін шақырады. Сондықтан Participants саны мен Join/Leave мәтіні detail жабылмай жаңарады.

## 9 Іздеу және тор

MeetingsTab where арқылы favourites, санат, past және іздеу сүзгілерін қолданады. Іздеу атауда регистрді ескермейді. toList жаңа тізім жасайды; sort тек сол көшірмені реттейді. Алдымен болашақ, кейін өткен кездесулер, әр топта күн бойынша орналасады.

Column ішінде іздеу, көлденең ChoiceChip қатары және Include past FilterChip бар. Expanded тізімге қалған биіктікті береді. Телефонда ListView.separated, 600 пиксельден бастап GridView.builder қолданылады. Баған саны қолжетімді енді 360-қа бөліп, жоғарыға дөңгелектеумен есептеледі; ұяшық 360 пиксельден кең болмайды. Шешімді LayoutBuilder қабылдайды.

MeetingCard Row ішінде avatar, Expanded мәтін және favourite батырмасын орналастырады. Атау екі жолдан аспайды, артық бөлігі ellipsis болады. Avatar Stack ішіндегі Positioned badge бес немесе аз орын қалса шығады. FULL — орын жоқ, N left — қалған орын саны. EmptyState іздеуде, таңдаулыларда және қатысушылар тізімінде қайта қолданылады.

## 10 Навигация және толық ақпарат

Маршрут мәтіндері тек routes.dart ішінде. Басқа файлдар Routes.home, Routes.detail, Routes.form тұрақтыларын қолданады. onGenerateRoute аргумент типін тексереді: DetailArguments немесе FormArguments. Белгісіз жол Not found бетіне барады.

Бір Navigator қолданылады. Сондықтан detail немесе form негізгі NavigationBar үстінен ашылады. AppBar артқа батырмасын автоматты түрде жасайды; қолмен BackButton немесе leading жоқ.

Detail header assets ішіндегі кітап иллюстрациясын көрсетеді; файл pubspec.yaml ішінде тіркелген. DefaultTabController About және Participants бөлімдерін басқарады. Профиль аты бос болса Join SnackBar көрсетеді. Оның Profile әрекеті shell tab-ын өзгертеді және detail-ді жабады.

## 11 Countdown және Timer

Countdown sealed class үш күйді анықтайды: Upcoming — әлі басталмаған; Started — басталғанына екі сағат толмаған; Ended — екі сағат өткен. Екі сағат — осы жобада қабылданған кездесу ұзақтығы, модельде жеке duration жоқ. Exhaustive switch әр күйдің мәтінін береді.

Detail initState ішінде бір Timer.periodic құрады. Әр минутта `_now` жаңарады. dispose timer.cancel шақырады. Бет жабылған соң таймер State-ке хабар жібермейді. format.dart күнді 18 Oct, 10:00 түрінде көрсетеді; минутқа padLeft қолданылады.

## 12 Форма валидаторлары

FormScreen item == null болса жаңа кездесу жасайды, әйтпесе өңдейді. Controllers және FocusNodes бір рет жасалып, dispose кезінде босатылады. Next келесі өріске өтеді, done немесе сыртқа басу пернетақтаны жабады.

Form GlobalKey<FormState> арқылы басқарылады. Save бір validate шақырады. Validator null қайтарса мән дұрыс, мәтін қайтарса қате көрсетіледі. Атау 3–60 таңба; орын міндетті; Online қосылса :// керек. Limit 1–500 аралығындағы бүтін сан және өңдеу кезінде қатысушылар санынан аз емес. Санат, күн және уақыт міндетті. Жаңа кездесудің уақыты болашақта болуы керек, ескісінің өткен күні сақтала алады.

ReadOnly күн мен уақыт өрістері picker ашады. Cancel null қайтарады, ескі мән өзгермейді. Save күннің year/month/day және уақыттың hour/minute мәндерін бір DateTime-ға біріктіреді. SingleChildScrollView пернетақта ашық болғанда Save-ге сырғытып жетуге мүмкіндік береді.

## 13 Сақтау және mounted

Save валидаторлардан өткенде нәтиже жасалады, `_saving = true` болады. Батырма өшіп, индикатор көрсетеді. Бір секунд күткеннен кейін mounted тексеріледі. false болса, экран жабылған; Navigator не setState шақырылмайды. Қайта басу `_saving` тексерісінен өтпейді.

Сәтті сақтау `_leaving = true` етеді. PopScope қайта құрылуы үшін келесі frame-ге callback қойылып, содан кейін Navigator.pop(context, result) жасалады. Шақырушы pushNamed<Meeting> нәтижесін await етеді, mounted пен null тексеріп, жаңа деректі сақтайды.

## 14 PopScope не салыстырады

`_snapshot` барлық мәтіндерді, күнді, уақытты, санатты, online мәнін жинайды. Мәтіннің ұзындығы да жазылады, сондықтан бөлгіш таңбалар салыстыруды бұзбайды. `_baseline` — форма ашылған сәттегі snapshot. `_dirty` олардың айырмашылығын салыстырады. Мәтінді өзгертіп қайта орнына қойсаңыз, форма қайта таза болады.

canPop: !_dirty. Таза форма сұрақсыз жабылады. Лас форма Discard changes? сұрайды; Cancel қалдырады, Discard шығарады. `_asking` бірнеше диалог ашылуын тежейді. Save `_leaving` арқылы dirty-ді false етеді, сондықтан сәтті сақтағанда артық сұрақ шықпайды. Android артқа жесті нақты құрылғыда бөлек тексерілуі керек.

## 15 Профиль және шектеулер

Ат міндетті, топ міндетті емес. Топ енгізілсе `^[A-Za-z]{2,8}-\d{2,4}$` RegExp үлгісіне сай болуы керек: 2–8 латын әрпі, дефис, 2–4 цифр. onSubmitted және Save profile бір әдісті шақырады. You are on N lists әр build сайын fold арқылы есептеледі.

Бұл зертханада адамның идентификаторы — аты. Профиль аты өзгерсе, бұрын тіркелген тізімдердегі аты бірге жаңарады. Set бірдей аттарды біріктіреді. Бірдей есімді екі нақты адамды ажырату мүмкін емес; өндірістік нұсқада userId керек болар еді. Бұл тапсырма List<String> талап етеді.

## 16 Тапсыруға дайындалу

REQUIREMENTS.md әр талаптың кодтағы орнын, DEFENCE_KK.md қорғаныс пулындағы 16 өзгерісті түсіндіреді. VERIFICATION.md нақты орындалған тексерулерді көрсетеді. README-дегі скриншоттар іске қосылған веб нұсқадан алынған.

git log --oneline арқылы жергілікті тарихты оқыңыз. GitHub-қа жіберу үшін өз репозиторийіңізді жасап, README-дегі remote және push командаларын қолданыңыз. Қорғауға дейін интернетсіз іске қосып, бірнеше өзгерісті AI көмегінсіз жасап көріңіз. Әр батырма қай callback шақыратынын және қай State өзгеретінін түсіндіре алуыңыз керек.
